# TIP-1143 execution profile

This document fixes the protocol choices implemented by evm2's unscheduled TIP-1143 profile. A
chain must activate the complete profile as one fork rule. `Version::with_tip1143(true)` enables
TIP-1143 and `RJUMP`/`RJUMPI`, installs the code limits, and installs the chunk tariffs.

## Limits and commitments

- Code up to 24,576 bytes remains one legacy record.
- Larger code uses a logical stride of 24,543 bytes. A full stored chunk is at most 24,576 bytes:
  24,543 logical bytes, 32 continuation bytes, and one layout byte.
- Runtime code has at most 40 chunks and 981,720 logical bytes.
- Initcode has a separate 2 MiB limit.
- The account retains the hash of the complete original runtime as its ordinary code hash.
- Large-code metadata stores the complete logical `code_size` and the ordered hash of every
  prepared chunk. The number of hashes must equal `ceil(code_size / 24,543)`.

The layout byte records how many leading bytes continue the instruction that started in the
preceding chunk. Its value is between 0 and 32 inclusive. Jump destination analysis begins after
these continuation bytes. Unused continuation bytes are zero.

Each chunk is validated against its account's total size and index. Adjacent chunks must agree on
the duplicated continuation bytes before execution or copying crosses the boundary. A missing,
mis-hashed, malformed, wrong-sized, or incoherent chunk is a fatal state-provider error.

## Instruction rules

`RJUMP` and `RJUMPI` are enabled with TIP-1143. Their two immediate bytes are base-219 digits from
the `DUPN`/`SWAPN` opcode alphabet: each byte decodes to a digit from 0 through 218 after subtracting
the alphabet offset. The combined value is interpreted as a balanced displacement from -23,980
through 23,980 and is relative to the position immediately after the instruction.

Legacy dynamic jumps retain legacy byte analysis after the chunk's continuation offset.

## Gas and ordering

The draft tariffs are 28,680 gas for a cold chunk and 1,000 gas for a warm chunk. Charging spends
the warm amount first, checks whether an unaffordable cold access can be skipped, loads and warms
the chunk, then spends the cold premium. Chunk warmth is transaction local and independent for
each account and chunk index.

| Operation | Account access | Chunk tariff |
| --- | --- | --- |
| Enter ordinary account code | Existing call/account rules first | Chunk 0 before execution |
| Fall through into another chunk | None | The destination chunk before activation |
| `CODESIZE` | None | None; total size is frame metadata |
| `CODECOPY` | None | Every intersected chunk, in increasing index order |
| `EXTCODESIZE` | Existing external-account rules first | Chunk 0 for legacy accounts; none for metadata-resident large code |
| `EXTCODECOPY` | Existing external-account and copy rules first | Every intersected chunk, in increasing index order |
| `EXTCODEHASH` | Existing external-account rules first | None |
| Native precompile | Existing call/account rules first | None |

An EIP-7702 designator remains account code and resolves before selecting the delegate's code.
Ordinary designator accounts therefore pay their own chunk tariff and then the applicable delegate
account and chunk tariffs. A designator stored at a native precompile address is inspected before
native-precompile dispatch without charging a chunk; when it delegates, native dispatch is disabled
and the delegate is charged normally.

## Fork migration

Before activation, chain state must backfill metadata and prepared chunks for every existing
runtime larger than 24,576 bytes, including code admitted under a previous 64 KiB limit. The
complete original bytes and their existing code hash remain unchanged. `AccountInfo::migrate_tip1143_code`
validates cached complete code and derives the account metadata; `prepare_code_chunks` returns the
prepared records that the state provider must persist by their commitment hashes.

Activation must not reinterpret metadata-free oversized code as legacy code. Such state indicates
an incomplete fork migration and chunk loading fails instead of silently choosing another
representation.
